בסיסי נתונים יחסיים (SQL) מול NoSQL

בבואנו לבנות אפליקציות ושרתים, בחירת מסד הנתונים הנכון היא החלטה ארכיטקטונית מכרעת. כיום קיימות שתי גישות מרכזיות לאחסון וניהול מידע:

מאפיין בסיס נתונים יחסי (SQL / Relational) NoSQL (מבוסס מסמכים - Document-oriented)
מבנה הנתונים טבלאות עם שורות ועמודות קבועות. סכמה נוקשה ומחייבת. מסמכים גמישים במבנה JSON (תחת המכסה כ-BSON). ללא סכמה קבועה.
ניהול קשרים מפתח ראשי (PK) ומפתח זר (FK). שליפה מורכבת באמצעות JOIN. קינון (Embedding) או קישור בעזרת מזהי מסמכים (Referencing).
עקביות (Consistency) עמידה מלאה בתקן ACID (עסקאות בטוחות, אטומיות ושלמות). עקביות בסופו של דבר (Eventual Consistency) לטובת ביצועים מהירים.
סקלביליות (Scaling) ורטיקלית (שדרוג חומרת השרת: עוד זיכרון ו-CPU). הוריזונטלית (ביזור הנתונים בין שרתים רבים - Sharding).
דוגמאות MySQL, PostgreSQL, SQLite. MongoDB, DynamoDB.
💡 כלל אצבע לבחירה: נבחר ב-SQL כאשר נדרש ניהול עסקאות מורכב שבו שלמות המידע קריטית (כגון מערכות בנקאות או רכישות באינטרנט). נבחר ב-NoSQL כאשר המבנה דינמי, נדרש פיתוח מהיר, או כאשר קצב הכתיבה לשרת גבוה מאוד.

עיצוב ומידול בסיסי נתונים (DB Design)

לפני שמתחילים לכתוב קוד, יש לתכנן את ישויות המידע באפליקציה בעזרת ERD (Entity-Relationship Diagram) המציג את הישויות (Entities), התכונות שלהן (Attributes), והקשרים ביניהן.

סוגי קשרים נפוצים:

  • קשר אחד-לאחד (1:1): למשל, User ופרופיל ייחודי Profile.
  • קשר אחד-לרבים (1:N): למשל, מחבר (Author) ופוסטים (Posts) שהוא כתב. בקשר זה נשמור מפתח זר בצד של ה"רבים" (בטבלת הפוסטים נשמור את מזהה המחבר - author_id).
  • קשר רבים-לרבים (M:N): למשל, סטודנטים (Students) וקורסים (Courses). בבסיסי נתונים יחסיים (SQL) קשר זה ממומש באמצעות **טבלת קישור** (Junction Table) המכילה את המפתחות של שתי הטבלאות.

נורמליזציה מול דה-נורמליזציה (NoSQL Design):

בבסיסי נתונים NoSQL, במקום לבצע פיצול טבלאות נוקשה (נורמליזציה) אנו בוחרים בין:

  • קינון (Embedding): שמירת אובייקטים בתוך אובייקטים (למשל, שמירת רשימת תגובות בתוך מסמך הפוסט). יתרון: שליפה מהירה ביותר בבקשה אחת. חיסרון: מוגבל בגודל המסמך (16MB במונגו) ועלול לגרום לכפילות נתונים.
  • קישור (Referencing): שמירת מזהה בלבד (מצביע למסמך אחר). יתרון: מונע כפילויות. חיסרון: דורש שליפות נוספות (Lookups) כדי לחבר את המידע.

מושגי ליבה ופעולות CRUD ב-MongoDB

MongoDB הוא מסד נתונים NoSQL המוביל בעולם המבוסס מסמכים. הוא מאחסן נתונים בפורמט BSON (בינארי דמוי JSON).

מינוחים בסיסיים:

  • Document (מסמך): רשומת הנתונים הבסיסית (מקביל לשורה ב-SQL).
  • Collection (אוסף): קבוצה של מסמכים (מקביל לטבלה ב-SQL).
  • _id: מפתח ייחודי אוטומטי מסוג ObjectId המיוצר לכל מסמך כדי להבטיח את ייחודיותו.
  • Index (אינדקס): מבנה נתונים מיוחד המאפשר האצה דרמטית של חיפושים באוסף.

שיטות CRUD בסיסיות (בשימוש הדרייבר של Node.js):

javascript 
// 1. יצירה (Create)
await db.collection('posts').insertOne({ title: 'My Post', published: true });
await db.collection('posts').insertMany([ { title: 'Post 2' }, { title: 'Post 3' } ]);

// 2. קריאה (Read) - שימוש ב-toArray לקבלת מערך
const allPosts = await db.collection('posts').find({ published: true }).toArray();

// 3. עדכון (Update) - חובה להשתמש באופרטור עדכון כמו $set
await db.collection('posts').updateOne(
  { _id: new ObjectId('...') }, 
  { $set: { title: 'New Title' } }
);

// 4. מחיקה (Delete)
await db.collection('posts').deleteOne({ _id: new ObjectId('...') });

אופרטורים של שאילתות ועדכונים ב-MongoDB

על מנת לבצע סינונים מורכבים ולעדכן נתונים בצורה יעילה מבלי להחליף את כל המסמך, MongoDB מספקת מגוון אופרטורים המתחילים בתו דולר ($).

אופרטורים להשוואה וסינון (Query Operators):

  • $gt (גדול מ...) | $gte (גדול או שווה ל...)
  • $lt (קטן מ...) | $lte (קטן או שווה ל...)
  • $ne (לא שווה ל...)
  • $in (מתאים לאחד הערכים במערך שסופק). דוגמה: { category: { $in: ['JS', 'Node'] } }
  • $exists (בודק האם שדה מסוים קיים במסמך). דוגמה: { discount: { $exists: true } }

אופרטורים לוגיים:

  • $or (מחזיר מסמך אם לפחות תנאי אחד מתקיים).
  • $and (מחזיר מסמך רק אם כל התנאים מתקיימים. שימושי בעיקר להצלבת תנאים מורכבים על אותו השדה).

אופרטורים לעדכון (Update Operators):

⚠️ שים לב: אם תבצע עדכון (Update) ללא אופרטורים, המסמך כולו יימחק ויוחלף באובייקט החדש ששלחת!
  • $set - מעדכן או מוסיף שדות ספציפיים בלבד, מבלי לפגוע בשאר המסמך.
  • $inc - מגדיל או מקטין ערך מספרי בצורה אטומית ובטוחה מפני בעיות סינכרון (concurrency). דוגמה: { $inc: { views: 1 } }
  • $push - מוסיף איבר למערך קיים.
  • $pull - מסיר איבר ממערך קיים.

MongoDB Compass & Atlas

1. MongoDB Atlas (ענן):

שירות בסיסי נתונים מנוהל בענן (DBaaS). הוא חוסך מאיתנו את הצורך להריץ ולנהל שרתים פיזית.

שלבי עבודה עיקריים עם Atlas:

  1. יצירת חשבון ובניית קלאסטר (Cluster) חינמי (M0).
  2. הגדרת Database Users (שם משתמש וסיסמה ייעודיים לגישה למסד הנתונים - נפרדים מפרטי הכניסה לאתר אטלס).
  3. הגדרת Network Access (חסימת IP / Whitelisting). לצורך בדיקות מקומיות מאשרים לרוב גישה מכל העולם על ידי הוספת הכתובת 0.0.0.0/0.
  4. העתקת מחרוזת החיבור (Connection String) המתחילה ב-mongodb+srv:// והצבתה בקובץ ה-.env של הפרויקט.

2. MongoDB Compass (ממשק גרפי):

כלי עזר ויזואלי המותקן על המחשב ומאפשר ניהול נוח של מסד הנתונים (מקומי או בענן) ללא כתיבת קוד.

  • CRUD ויזואלי: יצירה, עריכה ומחיקת מסמכים בקליק.
  • בניית שאילתות: כתיבת שאילתות סינון ומיון (Sort: 1 עבור סדר עולה, -1 עבור יורד).
  • Schema Analyzer: כלי המנתח את האוסף ומציג אילו סוגי נתונים קיימים בכל שדה ובאיזה אחוז מהמסמכים הם מופיעים.
  • Aggregation Pipeline Builder: ממשק לבניית שלבי אגרגציה מורכבים (שלב אחרי שלב) וייצוא שלהם ישירות לקוד JavaScript מוכן.

תבנית שרת Express משולב MongoDB

לפניך תבנית מלאה ונכונה לחיבור ושימוש ב-MongoDB בתוך שרת Express, המבוססת על החומר שנלמד בכיתה:

javascript 
import express from 'express';
import { MongoClient, ObjectId } from 'mongodb';

const app = express();
app.use(express.json()); // קריאת JSON ב-Body

const MONGO_URI = process.env.MONGODB_URI || 'mongodb://localhost:27017';
const client = new MongoClient(MONGO_URI);
let db;

// חיבור חד פעמי בכניסה לשרת
async function connectDB() {
  try {
    await client.connect();
    db = client.db('blog_db');
    console.log('Connected to MongoDB successfully!');
  } catch (error) {
    console.error('Failed to connect to database:', error);
    process.exit(1);
  }
}

// 1. קריאת פוסטים
app.get('/posts', async (req, res) => {
  try {
    const posts = await db.collection('posts').find({ published: true }).toArray();
    res.json(posts);
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

// 2. יצירת פוסט
app.post('/posts', async (req, res) => {
  try {
    const newPost = {
      title: req.body.title,
      content: req.body.content,
      createdAt: new Date()
    };
    const result = await db.collection('posts').insertOne(newPost);
    res.status(201).json({ _id: result.insertedId, ...newPost });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

// 3. עדכון פוסט לפי מזהה
app.put('/posts/:id', async (req, res) => {
  try {
    const id = req.params.id;
    if (!ObjectId.isValid(id)) {
      return res.status(400).json({ error: 'Invalid ID format' });
    }
    const updateResult = await db.collection('posts').updateOne(
      { _id: new ObjectId(id) },
      { $set: req.body }
    );
    if (updateResult.matchedCount === 0) {
      return res.status(404).json({ error: 'Post not found' });
    }
    res.json({ message: 'Post updated successfully' });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

// חיבור והפעלה
connectDB().then(() => {
  app.listen(3000, () => console.log('Server running on port 3000'));
});

עבודה עם Supabase (Backend-as-a-Service)

Supabase הוא תחליף קוד פתוח ל-Firebase המספק שרת מוכן עם מסד נתונים מסוג PostgreSQL, מערכת הרשאות, אחסון קבצים, וכתובות API מובנות ומאובטחות ישירות לבסיס הנתונים.

מאפיינים מרכזיים:

  • Row Level Security (RLS): מנגנון אבטחה המאפשר להגדיר ברמת מסד הנתונים בדיוק מי רשאי לקרוא, לכתוב או לעדכן כל שורה בטבלה. חוסך את הצורך בבניית קוד שרת מורכב לביצוע אימותים.
  • חיבור פשוט ל-Client: עבודה קלה באמצעות ספריית JavaScript רשמית.

שאילתות קשרים (JOIN) ב-Supabase:

אחד היתרונות הגדולים של Supabase (בהיותו מבוסס SQL) הוא היכולת לבצע קשרי גומלין ו-Joins בצורה אינטואיטיבית ישירות מהקליינט:

javascript 
import { createClient } from '@supabase/supabase-js';

const supabase = createClient(process.env.SUPABASE_URL, process.env.API_KEY);

// שליפת כל הפוסטים יחד עם פרטי המחברים שלהם (Join)
const { data, error } = await supabase
  .from('posts')
  .select('id, title, content, authors(id, firstname, lastname)');

if (error) {
  console.error('Error fetching posts:', error);
} else {
  console.log('Posts with authors:', data);
}
📌 בוחן הבנה מהיר: בקשר בין פוסט (Post) למחבר (Author), היכן נשמור את המפתח הזר (Foreign Key)?
